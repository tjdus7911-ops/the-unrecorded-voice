# 게임 엔진 선정 — Godot 4.7

> 결정일: 2026-11-26 · 상태: **채택 (변경 시 이 문서와 CLAUDE.md를 함께 갱신)**

## 결론

**Godot 4.7.2-stable (Forward+ 렌더러, GDScript)** 를 사용한다.
Blender 5.3에서 제작 → glTF 2.0(GLB)으로 내보내기 → Godot에서 직접 임포트하는 파이프라인.

## 비교

| 항목 | Godot 4.7 | Unity 6 | Unreal Engine 5 |
|---|---|---|---|
| 라이선스 비용 | 무료, MIT. 로열티 없음 | 매출 기준에 따라 유료 플랜 필요 | 일정 매출 초과 시 로열티 |
| Steam 출시 | 가능 (Windows/Linux 익스포트 + GodotSteam 확장) | 가능 | 가능 |
| Blender 연동 | glTF/GLB 네이티브, `.blend` 직접 임포트도 지원 | FBX 중심 | FBX/USD 중심 |
| 사실적 그래픽 상한 | 중상 (SDFGI·VoxelGI·볼류메트릭 포그·SSR·SSAO) | 상 (HDRP) | 최상 (Lumen·Nanite) |
| 실내 공포 장르 적합도 | 좁은 실내 + 손전등 + 정적 라이트 베이크에 충분 | 충분 | 과잉 스펙 |
| 개발 PC 요구사항 | 가벼움 (100MB 내외) | 중간 | 무거움 (수십~100GB, 고사양 GPU) |
| 클라우드 자동 테스트 | 리눅스 헤드리스 실행 가능 → **이 작업 환경에서 실제 테스트 가능** | 라이선스 활성화 필요 | 사실상 불가 |
| 텍스트 기반 씬/리소스 | `.tscn`/`.tres` 텍스트 → Git diff·AI 협업 용이 | YAML, 부분적 | 바이너리 `.uasset` |

## 선정 이유

1. **비용·라이선스 리스크 없음** — 상업 인디 출시 시 로열티·좌석 비용이 없다.
2. **AI 협업 개발에 적합** — 씬·리소스·스크립트가 모두 텍스트라 Claude가 직접 작성·검토·테스트할 수 있다. 클라우드 리눅스 환경에서 헤드리스로 임포트·자동 테스트를 실제로 돌릴 수 있다(Unity·Unreal은 불가).
3. **Blender 파이프라인 단순** — GLB 하나로 메시·PBR 재질·계층·피벗·애니메이션이 넘어오고, 메시 이름 접미사(`-col`, `-colonly`)로 충돌체를 Blender에서 지정할 수 있다.
4. **장르 요구사항 충족** — 이 게임의 핵심은 좁은 실내, 손전등 스팟라이트의 실시간 그림자, 절제된 조명, 3D 공간 음향이다. Godot 4 Forward+의 그림자·볼류메트릭 포그·라이트맵 베이크로 충분히 구현 가능하다.
5. **브라우저 테스트 재작업 최소화** — 같은 프로젝트를 Web 익스포트(Compatibility 렌더러)로 빌드할 수 있어 별도 코드베이스가 필요 없다. 단, 최종 품질 기준은 PC Forward+.

## 리스크와 대응

| 리스크 | 대응 |
|---|---|
| Unreal 대비 사실감 상한이 낮음 | 라이트맵 베이크(LightmapGI) + 고품질 PBR 텍스처 + 리플렉션 프로브 + 절제된 포스트프로세싱으로 보완. PHASE 01 렌더 비교로 검증 |
| 캐릭터 고급 셰이딩(피부 SSS·헤어) | Godot 4의 SSS·헤어 카드 셰이더로 대응, 캐릭터 단계에서 별도 검증 |
| Steam 연동 | GodotSteam(MIT) 사용 예정 — 출시 단계에서 도입 |

엔진 변경이 필요할 정도의 품질 격차가 PHASE 01 검토에서 확인되면, **에셋(Blender/GLB)은 그대로 재사용**하고 로직만 이식한다. 이를 위해 게임 데이터(대사·조명 상태·챕터)는 엔진 독립적인 JSON으로 관리한다.
