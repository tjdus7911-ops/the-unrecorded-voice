# 추가 개발 요구사항 — 공포 이벤트 및 스토리 트리거 시스템

기존 스토리, 공간, 캐릭터, 손전등, 1인칭 손과 팔, 음성 및 호흡 시스템에 공포 이벤트 시스템을 추가해 주세요.

공포 이벤트는 무작위로 발생하는 것이 아니라 스토리 진행과 플레이어 행동에 따라 발생하도록 설계합니다.

## 1. 이벤트 트리거 시스템

다음 조건을 기반으로 이벤트를 실행할 수 있도록 구현해 주세요.

- 특정 공간 진입
- 특정 위치 도달
- 문 열기
- 오브젝트 조사
- 단서 획득
- 녹음기 재생
- 녹음기 정지
- 테이프 교체
- 손전등 획득
- 손전등 켜기 및 끄기
- 전등 스위치 조작
- 특정 방향 바라보기
- 특정 방향에서 시선 돌리기
- 일정 시간 경과
- 이전 이벤트 완료
- 필수 단서 수집 완료

스토리 핵심 이벤트는 단순 시간 경과만으로 실행하지 않습니다.

플레이어가 필요한 행동을 완료하고 상황을 인지할 수 있는 상태에서 실행합니다.

## 2. 프롤로그 이벤트 구현 순서

EVENT 01 — 정상 작업실

모든 조명이 정상적으로 작동합니다. 플레이어는 자유롭게 이동하고 물건을 조사합니다. 기본 조작을 익힐 수 있도록 합니다.

EVENT 02 — 노크

기본 조작 튜토리얼 완료 후 출입문에서 세 번의 노크가 발생합니다.

정우의 대사: "이 시간에 누구지?"

문을 열면 복도에는 아무도 없고 택배 상자만 놓여 있습니다.

EVENT 03 — 테이프 재생

플레이어가 택배를 개봉하고 첫 번째 테이프를 삽입합니다.

아이들의 웃음소리와 그네 소리 이후 소은이의 목소리가 재생됩니다.

소은: "정우야, 녹음되고 있어?"

천장 조명이 한 번 짧게 깜빡입니다.

EVENT 04 — 등 뒤의 목소리

플레이어가 녹음기를 정지한 후 약 3초 뒤 플레이어 뒤쪽 공간에서 소은이의 음성이 재생됩니다.

소은: "정우야?"

정우가 순간적으로 숨을 들이마시는 효과음을 재생합니다.

플레이어가 뒤를 돌아보면 아무도 없습니다.

EVENT 05 — 이상 현상

등 뒤를 확인하면 벽시계가 멈추고 빗소리가 사라집니다.

모니터에 잡음이 발생하고 천장 조명이 불규칙하게 깜빡입니다.

출입문이 잠깁니다.

EVENT 06 — 정전

플레이어가 잠긴 출입문을 조사하면 모든 실내 조명이 꺼집니다.

전등 스위치를 눌러도 조명이 켜지지 않습니다.

책상 서랍에 있는 손전등을 찾도록 유도합니다.

손전등 획득 시 실제 손과 팔 애니메이션을 재생하고 F키 사용 방법을 안내합니다.

EVENT 07 — 실루엣

손전등을 획득하고 출입문에 접근하면 문 너머에서 어린아이의 그림자가 잠시 지나갑니다.

소은: "정우야, 여기야."

세 번의 노크가 다시 들립니다.

EVENT 08 — 공간 전환

출입문의 잠금이 해제됩니다.

플레이어가 문을 열면 손전등이 잠시 꺼지고 화면이 암전됩니다.

오래된 형광등이 켜지는 소리와 함께 1998년 아파트 복도로 전환합니다.

복도 끝에 소은이가 잠시 나타났다가 사라집니다.

TAPE 01 — 평범했던 하루 타이틀을 표시합니다.

프롤로그에서는 플레이어를 직접 공격하는 귀신을 등장시키지 않습니다.

## 3. 챕터별 공포 이벤트

TAPE 01: 실루엣, 혼자 움직이는 그네, 어린아이의 발소리, 순차적인 조명 소등. 직접 공격 없음.

TAPE 02: 경비실 TV 이상 현상, 열쇠 소리, 순찰자 등장, 주차장 정전, 첫 추격 및 은신 튜토리얼.

TAPE 03: 주민 가정집의 이상 현상, 사진 속 얼굴 변화, 방관자 등장, 전체 정전, 반복되는 복도.

TAPE 04: 전화벨, 지하 기계실 암흑 탐험, 손전등 단서 탐색, 차단기 복구, 관리인 등장, 출입문 잠금 및 추격.

TAPE 05: 어린 시절의 대화, 거울 속 어린 정우, 기억 속 소은의 등장. 추격 최소화.

TAPE 06: 공간 왜곡, 기존 귀신 재등장, 전체 정전, 잡음 등장, 최종 추격.

TAPE 07: 실제 사건 녹음 재생, 정우의 거친 호흡, 심장 박동, 정적, 마지막 선택 및 엔딩 분기.

## 4. 조명 제어 시스템

공간별 조명을 독립적으로 제어할 수 있도록 구현해 주세요.

- 정상 점등
- 한 번 깜빡임
- 불규칙한 깜빡임
- 순차적 소등
- 전체 정전
- 전등 고장
- 비상등 점등
- 전력 복구
- 스토리 이벤트에 따른 조명 변경

조명 상태와 스위치의 실제 작동 여부가 일치해야 합니다.

손전등은 일반적인 건물 정전의 영향을 받지 않습니다.

잡음과 관련된 특정 초자연적 이벤트에서만 일시적인 손전등 이상 현상을 허용합니다.

## 5. 귀신 등장 유형

귀신의 등장 상태를 구분해 주세요.

- 미등장
- 소리만 발생
- 그림자만 표시
- 멀리서 관찰 가능
- 플레이어 주변 순찰
- 플레이어 감지
- 추격
- 공격
- 탐색
- 소멸

스토리 연출용 귀신과 실제 공격 가능한 귀신을 구분합니다.

연출용 귀신이 플레이어를 의도치 않게 공격하지 않도록 합니다.

## 6. 공포 이벤트 데이터 관리

공포 이벤트를 코드에 하드코딩하지 않고 JSON 또는 Godot Resource 기반으로 관리해 주세요.

각 이벤트는 다음 정보를 가집니다.

- 이벤트 ID
- 챕터 ID
- 씬 ID
- 발생 조건
- 선행 이벤트
- 발생 지연 시간
- 조명 상태
- 등장 캐릭터
- 캐릭터 등장 위치
- 캐릭터 행동
- 음성 파일
- 효과음
- 환경음 변경
- 플레이어 호흡 상태
- 심장 박동 상태
- 상호작용 제한
- 이벤트 종료 조건
- 반복 가능 여부
- 체크포인트
- 다음 이벤트 ID

## 7. 이벤트 안정성

- 동일한 스토리 이벤트 중복 실행 방지
- 필수 단서 미획득 상태에서 다음 챕터 진입 방지
- 플레이어가 다른 방향을 보고 있어도 핵심 이벤트를 놓치지 않도록 처리
- 귀신이 플레이어 바로 앞에 부자연스럽게 생성되는 현상 방지
- 저장 및 불러오기 이후 이벤트 진행 상태 복원
- 추격 중 필수 스토리 이벤트 충돌 방지
- 이벤트 진행 불가 시 복구 로직 적용
- 과도한 점프스케어 반복 금지
- 조명 깜빡임 완화 설정 제공

## 8. 개발용 디버그 기능

개발 중 각 이벤트를 개별적으로 테스트할 수 있는 디버그 메뉴를 제작해 주세요.

- 이벤트 강제 실행
- 조명 상태 변경
- 귀신 등장
- 귀신 추격
- 음성 재생
- 환경음 변경
- 호흡 상태 변경
- 심장 박동 변경
- 체크포인트 이동
- 챕터 이동
- 이벤트 로그 확인

디버그 기능은 정식 출시 빌드에서 비활성화합니다.

## 9. 현재 개발 범위

현재는 작업실 및 외부 복도 제작 단계이므로 전체 챕터를 한 번에 구현하지 않습니다.

공포 이벤트 시스템의 공통 구조를 먼저 설계하고 프롤로그 EVENT 01~08을 실제 게임에서 구현해 주세요.

특히 정전, 손전등 획득, 등 뒤에서 들리는 목소리, 어린아이의 실루엣, 호흡 변화 및 공간 전환이 자연스럽게 연결되어야 합니다.

실제 Godot 플레이 영상과 Windows 테스트 빌드를 통해 전체 이벤트 흐름을 검토할 수 있도록 해 주세요.

기존 공간, 캐릭터, 스토리 및 그래픽 개선 요구사항은 그대로 유지합니다.
